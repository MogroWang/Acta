## 任务 1:启动窗口闪现 —— 能消除,方案如下

**诊断**(机制已有:visible:false + load 后双 rAF reveal + 隐藏期恢复窗口位置,均正常):残留闪现来自两个竞态——① WKWebView 在窗口隐藏时渲染被节流,`show()` 发生时首帧可能尚未合成,先露出原生底色 1~N 帧;② 前端 2.5s / Rust 3s 兜底触发时窗口以纯色先出现。

**修复(macOS 彻底解决,Windows 维持现状)**:
1. 新增 `src-tauri/tauri.macos.conf.json`(平台配置按 RFC 7396 合并,app.windows 数组整体替换,需完整复制窗口定义):主窗口 `"transparent": true`(去掉 backgroundColor)+ `"app": {"macOSPrivateApi": true}`。效果:webview 首帧绘出前即使窗口被显示也完全不可见,任何时序竞态都不再产生可见闪现。
2. `src-tauri/Cargo.toml`:tauri features 增加 `"macos-private-api"`(仅编译期,不本地构建)。
3. `src-tauri/src/lib.rs`:setup 中 `set_background_color` 用 `#[cfg(not(target_os = "macos"))]` 包裹(透明窗口不适用;Windows 保留主题底色兜底),并更新注释。
4. `src/splash.js`:macOS(UA 判断)在 load 后追加约 150ms 的定时 reveal(透明窗口下提前 reveal 无风险),不再苦等 rAF 节流或 2.5s 兜底;其余平台逻辑不变。
